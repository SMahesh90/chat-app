# ChatSphere  

Live Link : https://luminous-flow-production-d83c.up.railway.app/chat

Real-time one-on-one chat application built with Spring Boot, WebSocket (STOMP/SockJS), React, and MySQL.

---

## 📌 Overview

ChatSphere is a full-stack messaging application that goes beyond typical CRUD portfolio projects by implementing genuine real-time, bidirectional communication. Authenticated users can add each other as friends and exchange live messages, with instant delivery, typing indicators, online/offline presence, and read receipts — all backed by a persistent message history stored in MySQL. The project was built to demonstrate practical experience with WebSocket-based systems, JWT security applied across both REST and WebSocket layers, and a decoupled React + Spring Boot architecture.

---

## ✨ Features

- **JWT Authentication** — Register/login with hashed passwords (BCrypt) and stateless token-based sessions.
- **Friend System** — Search users by username, send/accept friend requests, and view an accepted friends list.
- **Real-Time Messaging** — Instant one-on-one message delivery over a STOMP-over-WebSocket connection.
- **Persistent Chat History** — All messages stored in MySQL and retrievable via a paginated REST endpoint.
- **Online/Offline Presence** — Live presence updates broadcast on WebSocket connect/disconnect.
- **Typing Indicators** — Real-time "user is typing..." events with automatic timeout-based clearing.
- **Read Receipts** — Messages tracked as `SENT`/`READ`, with checkmark indicators (✓ / ✓✓) in the UI.
- **Automatic Reconnection** — The frontend STOMP client auto-reconnects on connection loss, with a visible "Reconnecting..." banner.
- **Secure WebSocket Handshake** — A custom interceptor validates JWTs before a WebSocket connection is even accepted, not just on REST calls.

## 🔌 API Documentation

| Method | Endpoint | Purpose | Auth |
|---|---|---|---|
| POST | `/auth/register` | Register a new user | ❌ |
| POST | `/auth/login` | Login, returns JWT | ❌ |
| GET | `/friends/search?query={text}` | Search users by username | 🔒 |
| POST | `/friends/request` | Send a friend request | 🔒 |
| POST | `/friends/accept` | Accept a pending request | 🔒 |
| GET | `/friends/list` | Get accepted friends | 🔒 |
| GET | `/friends/pending` | Get incoming requests | 🔒 |
| GET | `/messages/history/{username}?page=0&size=20` | Paginated chat history | 🔒 |

| GET | `/status/{username}` | Get online/offline status | 🔒 |
 
**WebSocket** (`/ws?token={jwt}`):
 
| Direction | Destination | Purpose |
|---|---|---|
| Send | `/app/chat.send` | Send a message |
| Send | `/app/chat.typing` | Broadcast typing state |
| Subscribe | `/user/queue/messages` | Receive incoming messages |
| Subscribe | `/user/queue/typing` | Receive typing events |

## 🔑 Authentication & Authorization
- Passwords hashed with `BCryptPasswordEncoder` — never stored in plaintext.
- Stateless JWT issued on login/register, used for both REST and WebSocket auth.
- `JwtAuthFilter` validates the `Authorization` header on every protected REST request.
- `JwtHandshakeInterceptor` validates the JWT **before** a WebSocket handshake completes — unauthenticated clients are rejected at connection time, not after.
- `CustomHandshakeHandler` maps the authenticated username onto the STOMP session's `Principal`, enabling targeted message delivery via `convertAndSendToUser(...)`.
- CORS is explicitly scoped to the known frontend origin rather than left open.
## 🧪 Testing
Manually tested throughout development via:
- Postman for all REST endpoints (register, login, friend flow, message history, mark-as-read).
- Two concurrent browser sessions (regular + incognito) to verify real-time bidirectional messaging, typing indicators, presence updates, and reconnection behavior.
No automated test suite exists yet. Recommended future setup: JUnit 5 + Mockito (`spring-boot-starter-test`) for the backend, and Vitest + React Testing Library for the frontend.
 
## ⚡ Performance & Design Decisions
- **STOMP over raw WebSocket** was chosen for built-in subscription/destination routing, avoiding the need to hand-roll a message-routing protocol.
- **JWT passed as a WebSocket query parameter** (rather than a header) because the WebSocket handshake in browsers cannot carry custom headers — this is a standard, necessary pattern for authenticating WebSocket connections.
- **`receiverUsernameRef` (a `useRef` mirror of state)** is used on the frontend so that WebSocket event callbacks — registered once on mount — always read the *current* conversation partner instead of a stale value captured at connection time.
- **`onWebSocketClose` over `onDisconnect`** was chosen for detecting connection loss on the frontend, since `onDisconnect` did not reliably fire during failed reconnection attempts in testing.
- **Explicit `deactivate()` on logout** ensures the WebSocket session closes cleanly, so presence status updates correctly instead of leaving a "ghost" online session.
## 🚧 Known Limitations
- JWT signing secret is hardcoded rather than externalized — not production-safe as-is.
- No automated test suite.
- Friend search uses `findAll()` with in-memory filtering rather than a database-level query — won't scale with a large user base.
- No group chat — one-on-one conversations only.
- No file/image sharing — text-only messages.
- No message editing or deletion.
- Presence broadcasts (`/topic/status`) are global rather than scoped to a user's friends.
- No rate limiting on authentication endpoints.
- Not yet deployed to a live/public environment.
